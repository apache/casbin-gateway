# 3.3 No API key: the caller's own login

An agent signed in with a ChatGPT or Claude subscription has no API key to paste. It does not need one.

Set the provider's **Authentication** to **the caller's own login**:

- The base URL points at the vendor.
- Every request is forwarded with the credentials **the agent itself sent**, so it keeps its own sign-in.
- Leave **Models** empty and the provider accepts any model name.

Gateway records and routes that traffic exactly as it does for a provider with a key. It just never sees one.

## The environment snippet is shorter

For such a provider the snippet sets the base URL and nothing else:

```bash
export ANTHROPIC_BASE_URL="http://localhost:17000/v1/agents/claude-code"
```

A token there would **replace** the sign-in the agent already has, which is the one thing this mode exists to keep.

## What you still get

Everything except holding the key:

- LLM Records, in full ([4.2](../4-governance/4.2-llm-records.md)).
- Permissions over tools, models and providers ([4.1](../4-governance/4.1-permissions.md)).
- Usage from the relayed traffic, on top of what the transcripts already gave you ([4.3](../4-governance/4.3-usage-and-pricing.md)).

## The exception

**Codex.** Its ChatGPT sign-in talks to an endpoint no provider stands in for, so a Codex CLI still needs a provider with an API key.

Codex's spend is still on the [Usage](../4-governance/4.3-usage-and-pricing.md) page either way, because that page reads the agent's own transcripts rather than the relay.
