# 5.1 设置与配置

**所有配置都是可选的。**设置在**设置**页改，存在数据库里，所以不需要手工编辑文件，也不需要重启。

## 文件和页面的关系

可执行文件旁边的`conf/app.conf`只在**第一次启动**时给设置**播种**，并且逐项写了说明。一键安装的目录里没有这个文件，改用编译进二进制的那份来播种。

第一次启动之后再改这个文件不起作用——除了那几个在数据库打开之前就要读的键：

`httpport`、`driverName`、`dataSourceName`、`dbName`、`redisEndpoint`。

## 真正会被改的那些

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `httpport` | `17000` | Web界面和REST API的端口 |
| `httpaddr` | `127.0.0.1` | Web界面绑定的网卡——见[5.2](5.2-security-and-network.md) |
| `driverName` / `dataSourceName` | `sqlite` / `./data/casbin-gateway.db` | 数据存在哪 |
| `llmRecordMode` | `full` | 每个转发请求保留多少——[4.2](../4-governance/4.2-llm-records.md) |
| `providerProbeMode` | `auto` | 供应商是自动探测、只在要求时探测（`manual`），还是从不探测（`off`）——[3.4](../3-providers/3.4-authenticity.md) |
| `apiKeyEncryptionKey` | 空 | 用AES-256-GCM加密落盘的供应商API Key |
| `casdoorEndpoint` | 空 | 把登录切换到[Casdoor](https://casdoor.org)单点登录 |

## 设置页逐节说明

| 小节 | 内容 |
| --- | --- |
| **开机自启动** | 登录这台机器时要不要启动Gateway。托盘菜单的**Start at Login**是同一个开关 |
| **LLM记录** | 记录模式和相关限制——[4.2](../4-governance/4.2-llm-records.md) |
| **渠道探测** | 探测模式，以及报告多久过期——[3.4](../3-providers/3.4-authenticity.md) |
| **Agent** | Agent状态目录、保留多少条活动记录、监控轮询间隔 |
| **登录** | Casdoor的五个字段；留空则用Gateway自己的用户表 |
| **安全** | `apiKeyEncryptionKey`和中继令牌——[5.2](5.2-security-and-network.md) |
| **网络** | 出站SOCKS5代理、允许的主机名、允许的来源 |
| **备份** | 配置快照——[5.3](5.3-backups.md) |
| **云同步** | 把每份备份再存一份到这台机器之外——[5.3](5.3-backups.md) |
| **导入与导出** | 把配置作为一个文件搬到另一台机器，或从那边读回来 |

## 用MySQL代替SQLite

用的是XORM，所以它支持的数据库都能用。把Gateway指向你的服务器，`dbName`不存在时会在第一次启动时创建：

```ini
driverName = mysql
dataSourceName = root:123@tcp(localhost:3306)/
dbName = casbin_gateway
```

## 接入Casdoor

[Casdoor](https://casdoor.org)是可选的，接管成员管理。在一个Casdoor实例里为Gateway建好组织和应用，然后填**设置→登录**的五个字段。

只要`casdoorEndpoint`一填，登录就会跳转到Casdoor，同时也就启用了[OAuth登录](https://casdoor.org/docs/provider/oauth/overview)。

## 与其查文件，不如看结果

启动摘要会报告Gateway实际在做什么：用的哪个端口、哪个数据库、设置从哪来、中继要不要令牌（[1.2](../1-getting-started/1.2-installation.md)）。
