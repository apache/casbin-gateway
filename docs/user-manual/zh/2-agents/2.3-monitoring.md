# 2.3 监控、会话与活动记录

两份不同的记录，来自两个不同的源头：

| 页面 | 来源 | 需要 |
| --- | --- | --- |
| **会话** | Agent本来就会写在磁盘上的会话记录 | 什么都不需要 |
| **活动记录** | Gateway装进Agent里的监控钩子 | 该Agent开启监控 |

这两者都不等于[LLM记录](../4-governance/4.2-llm-records.md)——那一页是Gateway自己转发出去的东西。

## 会话

这些Agent的每一次会话，读自它们自己的会话记录：整段对话，一条一条，带每一轮用掉的token。

页面会统计一共有多少次会话、今天跑了多少、其中多少来自会话记录而不是监控，并且可以筛到某一个Agent或某一个来源。

因为会话记录不管Gateway在不在路径上都会写，所以这一页覆盖那些完全没走Gateway的会话——包括用自己订阅的Agent。

## 监控

监控按Agent开启，在它的卡片上或它自己的页面上。Gateway会在那个Agent自己的配置里装一个钩子，此后记录它做了什么：提示词、工具调用，以及它弹给你的权限询问。

这是**只读审计**。Agent做任何事都不会等Gateway，开了监控也不会改变任何回答。

不是每个Agent都支持——[README](../../../../README_zh.md#每个-agent-支持到什么程度)那张表的**监控**列是当前清单。

关掉监控会把钩子从该Agent的配置里去掉。`casbin-gateway uninstall`会对所有Agent一次性做同样的事（[5.5](../5-operations/5.5-lifecycle.md)）。

## 活动记录

**活动记录**是被监控的Agent此刻正在做什么：每一次工具调用、调用的对象、耗时多久。

Agent正在跑的时候就该开着这一页——一次长时间的自动执行，在这里读起来是一份"它到底动了什么"的清单，而不是终端里刷屏的输出。

## 钩子同时也是一个执行点

不把模型流量走Gateway的Agent，**工具**开关仍然对它生效：Gateway装的那个钩子会在工具真正执行前先问Gateway一次，开关不允许的调用会被拒掉。

模型和供应商这两类规则不一样：它们只能约束走代理的请求。权限页会说明某个Agent属于哪种情况（[4.1](../4-governance/4.1-permissions.md)）。
