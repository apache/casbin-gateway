# 3.2 让Agent的流量走Gateway

把流量接进来，才有[LLM记录](../4-governance/4.2-llm-records.md)，[权限](../4-governance/4.1-permissions.md)里的模型和供应商规则才有东西可管，Gateway也才能替Agent保管厂商的Key。

## 两种接法

### 让Gateway改写Agent的配置

**Agent客户端**→打开一个Agent→选一个供应商→**写入配置**。

对于Gateway认得其配置格式的Agent，这一步会按该Agent的格式，把端点和令牌写进它自己的文件。

- **预览**先把要写的内容原样给你看。
- **恢复**撤销这次写入。
- 之后换一个供应商，文件当场重写，所以从此切换只需一次点击，两个页面上都能切。

### 你自己导出两个环境变量

其他Agent，页面会给出已经填好真实值的环境变量片段。在带着它的shell里启动Agent：

```bash
export ANTHROPIC_BASE_URL="http://localhost:17000/v1/agents/claude-code"
export ANTHROPIC_AUTH_TOKEN="cg-..."
```

这个token是**Gateway自己的中继令牌，不是厂商的Key**。Agent那个变量为空就不肯启动，而Gateway对上游用的是供应商的Key。

## 一个基础URL，四套API

Agent的基础URL是`/v1/agents/<agent-id>`，具体响应哪套，取决于客户端请求的路径：

| Agent说的协议 | 它请求 | 典型客户端 |
| --- | --- | --- |
| OpenAI Chat Completions | `/chat/completions` | Cline、Continue、Zed、Aider、goose等大多数 |
| Anthropic Messages | `/v1/messages` | Claude Code |
| OpenAI Responses | `/responses` | Codex——它放弃chat completions之后只说这一套 |
| Google Gemini | `/v1beta/models/<model>:generateContent` | Gemini CLI——只说Google自家的API |

**供应商提供的API不必是同一套。**Gateway在这四套之间双向转换，流式回答也一样。于是下面这些都成立：

- Codex跑在DeepSeek、Kimi或Qwen上。
- Claude Code跑在其中任意一个上。
- Gemini CLI跑在一个从没听说过Google API的供应商上。

如果供应商提供的正是请求进来时的那套API，就**逐字节原样转发**，因为没什么要转换的。

Gateway唯一自己回答的，是Anthropic和Gemini客户端在每轮之前问的token计数；绑定的供应商没有对应端点时，它自己估算。

## 一个请求经历了什么

1. **鉴权**——校验中继令牌，来自本机的请求除外（[5.2](../5-operations/5.2-security-and-network.md)）。
2. **校验**——按该Agent的权限检查模型、供应商，以及请求里带的工具（[4.1](../4-governance/4.1-permissions.md)）。被关掉的工具会在请求离开这台机器之前被摘掉。
3. **转换**——供应商说的是另一套API时。
4. **转发**——用供应商的Key。
5. **记录**——按`llmRecordMode`规定的深度（[4.2](../4-governance/4.2-llm-records.md)）。

请求里要的东西被关掉时，返回的是Agent所说那套API里的`permission_error`，所以它读起来是一次拒绝，而不是网关坏了。

## 之后换Key

Agent都指向Gateway之后，Key只存在于一个地方。改一次供应商，所有绑定它的Agent在下一个请求就跟着变，不用碰任何Agent的配置。
