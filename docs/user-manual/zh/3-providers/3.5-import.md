# 3.5 导入配置与链接

**导入配置**接受两种东西：本机上一份CC Switch安装里的全部内容，以及厂商"添加此项"链接携带的东西。两者都会**先展示出来，你不点就什么都不写**。

## 从CC Switch导入

如果这个账户下装了CC Switch，页面会告诉你，并列出它保存的东西：供应商、MCP服务器、指令和技能来源。

- 勾选要搬过来的，或者**全选**。
- CC Switch**只被读取**，原样不动。
- 这边已经有同名条目的，会标出来，而不是悄悄覆盖。
- Gateway接不下来的那一行会明说，而不是无声失败。

## 从链接导入

厂商在自己页面上放"添加到我的Agent管理器"按钮，点开的是一个`ccswitch://`链接而不是网页。Gateway直接读这个格式，而不是再发明一套没人会给按钮的格式。

一条链接可以携带四类东西中的任意一类：

| 类型 | 带过来什么 |
| --- | --- |
| **供应商** | 基础URL、Key和模型列表 |
| **MCP服务器** | 写服务器用的那段JSON，包括它将要运行的参数 |
| **指令** | 一份供Agent在每次会话前阅读的指令 |
| **技能来源** | 一个用来安装技能的仓库——加进来本身不安装任何东西 |

链接携带的一切都会在写入之前摊开给你看：MCP服务器将以什么参数运行、指令的完整内容、技能会从哪个仓库来。链接来自网站，所以它的值先读给你听。

- **供应商**会被送到供应商表单，在那里复核并对上游探测之后才存下来。
- 另外三类走的是和手动添加完全相同的接口，写进你勾选的那些Agent。
- 链接里点名的是应用而不是本机的Agent，其中Gateway不管的那些会**明确报回给你**，而不是悄悄丢掉。

## 在网页上点这种链接

Gateway启动时会在Windows和Linux上认领`ccswitch://`协议，所以点这种按钮会打开Gateway的导入页，内容已经摊好。

- 这个协议只在**第一次**从原持有者那里接过来，Gateway被卸载时再还回去。
- 如果注册项本来就是Gateway自己的，每次启动都会重写一遍——因为它记录的是一个路径，而升级或搬家会让这个路径指向一个已经不在那儿的Gateway。
- **macOS上完全不认领**：那里的URL协议属于应用程序包，链接以Apple事件的形式送达，而这个启动器没有接收它的循环；声明了反而会把链接从真正打得开它的程序手里抢走。

改用导入页上的**粘贴链接**框，所有平台都可以。供应商页也同样接受一条供应商链接。

## 为什么链接不放在地址栏里

链接是放在API调用的请求体里交给Gateway的，而不是放在它打开的那个页面的地址里——因为供应商链接携带API Key，而地址会留在浏览器历史里，并且会被带到这个页面接下来跳转的任何地方。
